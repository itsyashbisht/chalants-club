# Chalants Club · travel circle booking

India-first booking product for hosted group trips for singles. Built from [docs/PRD.md](docs/PRD.md), [docs/design.md](docs/design.md) and [docs/TRD.md](docs/TRD.md). Flow: nine-question quiz → ranked departures → 30% deposit (Razorpay order 1) → human verification → balance (Razorpay order 2) → confirmed seat and private circle.

Stack: Next.js 16 App Router (Turbopack), React 19, strict TypeScript, Tailwind 4, Clerk, Postgres (Neon pooled in staging/production) with Drizzle + `pg`, Zod, Razorpay REST (fetch, Basic auth), Resend, Vitest. Live payments are disabled by default and refused unless `PAYMENTS_LIVE_ENABLED=true` with a live key.

## Layout

```
src/app            thin route entry points (route groups: (public), (auth), (member), admin, api)
src/features       trips · quiz · bookings · verification · payments · circle · support
                   each owns schema.ts, service/queries, client components and tests
src/components/ui  shared primitives (buttons, fields, notices, status panel, cards)
src/lib            env, db (client/tx/schema), auth, email, razorpay client + fake, jobs, http, rate limit
drizzle/           checked-in SQL migrations (generated by drizzle-kit, snake_case casing)
scripts/           migrate, reset (local only), seed (pilot fixtures), tick
docs/              PRD, design, TRD, implementation handoff
```

## Local setup

Requirements: Node 24, pnpm 12, Docker (for Postgres) or any Postgres 16.

```bash
docker run -d --name chalants-pg -e POSTGRES_PASSWORD=postgres -p 5433:5432 postgres:16-alpine
```

```bash
cp .env.example .env.local
```

Set `AUTH_DEV_BYPASS=true` in `.env.local` to test without Clerk (a cookie identifies the signed-in email; never honoured in production). Then:

```bash
pnpm install
```

```bash
docker exec chalants-pg psql -U postgres -c "create database chalants_dev"
```

```bash
pnpm db:migrate
```

```bash
pnpm db:seed
```

```bash
pnpm dev
```

Seeded staff for the dev bypass: `operator@example.test` (operator, finance, reviewer), `reviewer@example.test`, `finance@example.test`, `host@example.test`. Any other email becomes a traveller. The seed creates Udaipur and Himalayan pilot departures including a one-seat departure for race testing.

## Payments (Razorpay Test Mode)

1. In the Razorpay dashboard (Test Mode) create API keys; set `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` and `NEXT_PUBLIC_RAZORPAY_KEY_ID` (same key ID). Keep `RAZORPAY_MODE=test`.
2. Enable automatic capture in Settings → Payment capture (both environments). The app only applies payments whose provider status is `captured`.
3. Register a webhook pointing at `https://<host>/api/webhooks/razorpay` with a secret (`RAZORPAY_WEBHOOK_SECRET`) and these events: `payment.captured`, `payment.failed`, `payment.authorized`, `order.paid`, `refund.created`, `refund.processed`, `refund.failed`. During rotation put the old secret in `RAZORPAY_WEBHOOK_SECRET_PREVIOUS`.
4. Optionally set `RAZORPAY_ACCOUNT_ID` to reject events for other accounts.
5. Test and live must use separate deployments/databases and separate webhook endpoints.

Refunds are submitted with `X-Refund-Idempotency` set to the refund operation UUID via a direct authenticated request (the official SDK cannot set per-request headers).

## Scheduler

`GET /api/internal/jobs/tick` with `Authorization: Bearer <SCHEDULER_SECRET>` runs one bounded tick: reconcile payable orders near expiry → expire holds and balance windows → escalate overdue reviews → drain the webhook inbox → deliver the outbox (emails, alerts, refund submissions) → reconcile stuck refunds. A Postgres lease prevents overlap.

Correctness does not depend on the tick: every booking request checks deadlines itself (lapsed holds are closed when someone books the same departure or opens the booking, and seat availability ignores lapsed holds). The tick only decides how quickly emails, refunds and reconciliation happen.

Where it runs:

- `vercel.json` schedules a daily safety-net run (Vercel Hobby allows one cron per day). Set `CRON_SECRET` to the same value as `SCHEDULER_SECRET`; Vercel sends it as the bearer token.
- `.github/workflows/tick.yml` calls the endpoint every five minutes (best effort). Add `APP_URL` and `SCHEDULER_SECRET` as repository secrets.
- For minute precision use an external scheduler such as cron-job.org with the same URL and bearer header, or a Vercel Pro cron with `* * * * *`.

The admin payments page shows scheduler health (last tick time).

## Auth and roles

Clerk via `src/proxy.ts` (`clerkMiddleware`). Roles live in `user_roles` (host, reviewer, finance, operator); grants are audited. `BOOTSTRAP_OPERATOR_EMAILS` grants operator on first sign-in for the pilot. In production with Clerk configured, staff actions require MFA on the Clerk account.
